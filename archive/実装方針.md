# ROSETTA Candidate Search — 実装方針書

## 概要

論文等のテキストから抽出された脳領域・解剖学的構造の名称を、HOMBA（Harmonized Ontology of Mammalian Brain Anatomy）の標準タームへ自動変換するシステムの設計方針を定める。

HOMBAは Allen Institute が開発した、2341の脳・脊髄構造を含む階層的な種横断オントロジーである。ヒト・霊長類・げっ歯類の構造間で用語が統一されており、同義語情報を含む。

## アーキテクチャ概要

3段階のパイプライン構成を採用する。

```
Input text mention
       │
       ▼
┌─────────────────────────┐
│  Stage 1: 前処理         │
│  正規化・略語展開・トークン化 │
└─────────┬───────────────┘
          │
          ▼
┌─────────────────────────────────────┐
│  Stage 2: 候補生成 (top-K recall)     │
│  完全一致 / あいまいマッチ / BM25     │
│  → union + dedup → top-K (~50)      │
└─────────┬───────────────────────────┘
          │
          ▼
┌─────────────────────────────────────┐
│  Stage 3: セマンティックリランキング    │
│  SapBERT embedding + cosine sim     │
│  + 階層構造ブースト                   │
│  → confidence threshold → 出力      │
└─────────────────────────────────────┘
```

---

## Stage 1: 前処理

### 目的

論文中の脳領域名の表記ゆれを吸収し、後段の検索精度を高める。

### 処理手順

1. **ケース正規化**: 全て小文字に統一。ただしローマ数字（V1, BA17）やアクロニムは内部的に保持する。
2. **記号・空白の正規化**: ハイフン、スペース、アンダースコアの統一（`dorso-lateral` → `dorsolateral`）。括弧内の補足情報（`area 46 (dlPFC)` など）の分離。
3. **左右・半球情報の分離**: `"left hippocampus"` → `query="hippocampus"`, `laterality="left"`。laterality はメタデータとして保持し、マッピング本体には含めない。
4. **略語展開**: 辞書ベースで略語をフルネームに展開する。これが本ステージで最も重要。

### 略語辞書の構築

神経科学は略語が極めて多い。以下のソースから辞書を構築する。

| ソース | 内容 | 例 |
|--------|------|-----|
| 手動キュレーション | 頻出略語 ~500 件 | dlPFC → dorsolateral prefrontal cortex |
| NeuroNames | BrainInfo の同義語テーブル | CA1 → cornu ammonis 1 |
| HOMBA synonym列 | HOMBA CSV 内の同義語 | — |
| 論文コーパスからの自動抽出 | `"XXX (略語)"` パターン | SMA → supplementary motor area |

略語は文脈依存（`SN` = substantia nigra / sinoatrial node）であるため、脳科学文脈限定の辞書とする。曖昧なケースは候補を複数展開して Stage 2 に渡す。

---

## Stage 2: 候補生成

### 目的

高い再現率（recall）で候補を広く拾う。精度は Stage 3 に委ねる。

### 3つの並列戦略

#### 2a. 完全一致 / エイリアス辞書ルックアップ

HOMBA の公式名（`name`列）、略称（`acronym`列）、同義語（`synonym`列）を全てキーとするハッシュマップを構築し、正規化済みクエリで直接ルックアップする。

```python
# 疑似コード
alias_map: dict[str, list[HOMBATerm]] = build_alias_map(homba_csv)
candidates_exact = alias_map.get(normalized_query, [])
```

当たれば最速・最も確実。大半のケースはここで解決する見込み。

#### 2b. あいまい文字列マッチング

完全一致で当たらなかった場合に発動。以下のいずれかを使用する。

- **Jaro-Winkler 類似度**: 先頭一致を重視。短い名称の typo に強い。
- **Character n-gram overlap (n=2,3)**: 部分文字列の共有率で評価。語順に依存しない。
- **Levenshtein 距離（正規化）**: 編集距離ベース。文字数が大きく異なる候補を排除できる。

実装上は、HOMBA の全ターム（+ synonym）に対してスコアを計算し、上位 K 件を返す。ターム数が 2341 + synonyms ≒ 数千件程度なので、全件走査でも十分に高速。

```python
# 疑似コード
from rapidfuzz import fuzz
scores = [
    (term, fuzz.jaro_winkler_similarity(query, term.normalized_name))
    for term in homba_terms
]
candidates_fuzzy = top_k(scores, k=30)
```

#### 2c. BM25 / トークンレベルマッチング

複合名（multi-word term）の部分一致に対応する。語順が異なるケースに強い。

例: `"dorsolateral prefrontal cortex"` vs `"prefrontal cortex, dorsolateral part"`

HOMBA の全ターム名を「文書」としてBM25インデックスを構築し、クエリのトークンで検索する。

```python
# 疑似コード
from rank_bm25 import BM25Okapi
corpus = [term.tokenized_name for term in homba_terms]
bm25 = BM25Okapi(corpus)
candidates_bm25 = bm25.get_top_n(query_tokens, n=30)
```

### 候補の統合

3 戦略の結果を union し、重複を排除して上位 K 件（K ≒ 50）を Stage 3 に渡す。

各戦略のスコアはスケールが異なるため、この段階ではランキングの統合は行わず、候補集合の網羅性を優先する。

---

## Stage 3: セマンティックリランキング

### 目的

候補集合の中から、意味的に最も適切な HOMBA ターム を選出する。

### 3a. 埋め込みモデルの選択

汎用の埋め込みモデル（OpenAI text-embedding, Sentence-BERT 等）ではなく、生物医学シソーラスで対照学習されたモデルを使用する。

| モデル | 特徴 | 推奨度 |
|--------|------|--------|
| **SapBERT** | UMLS の同義語ペアで self-alignment pre-training。生物医学エンティティ正規化の SOTA 基盤 | ◎ |
| **BioLORD** | 定義文 + 同義語で学習。解剖学的概念の意味的距離に優れる | ○ |
| **CODER** | 対照学習 + 関係予測。UMLS 関係も学習 | ○ |
| 汎用モデル (e.g. OpenAI) | 解剖学的同義語の近さを十分に捉えられない | △ |

推奨: **SapBERT** をベースライン、**BioLORD** を比較対象として評価する。

### 3b. スコアリング

```python
# 疑似コード
query_emb = model.encode(normalized_query)           # shape: (d,)
cand_embs = model.encode([c.name for c in candidates]) # shape: (K, d)

# cosine similarity（正規化済みなら内積と等価）
cos_scores = cosine_similarity(query_emb, cand_embs)  # shape: (K,)
```

**cosine 類似度 vs 内積**: ベクトルのノルムに意味がないタスクなので cosine 類似度を採用する。SapBERT の出力を L2 正規化しておけば内積と等価になるため、実装上はどちらでもよい。

### 3c. 階層構造ブースト (Hierarchy-Aware Boost)

HOMBA は階層的オントロジーであり、入力テキストの粒度と候補の粒度の一致度をスコアに反映する。

```
brain
 └── cerebral cortex
      └── frontal lobe
           └── prefrontal cortex
                └── dorsolateral prefrontal cortex
```

入力が `"frontal lobe"` のとき:

- `"frontal lobe"` そのもの → ブースト大（同一レベル）
- `"prefrontal cortex"` → ブーストなし（直接の子）
- `"dorsolateral prefrontal cortex"` → ペナルティ（2レベル下、粒度の不一致）
- `"cerebral cortex"` → ペナルティ（上位概念への過度な汎化）

```python
def hierarchy_boost(query_depth_estimate, candidate_depth, cos_score):
    depth_diff = abs(query_depth_estimate - candidate_depth)
    penalty = depth_diff * ALPHA  # ALPHA: ハイパーパラメータ（0.02〜0.05程度）
    return cos_score - penalty
```

クエリの粒度推定には、トークン数やテキスト中の修飾語の有無を手がかりとする。

### 3d. 最終スコアと出力

```python
final_score = w1 * cos_score + w2 * hierarchy_boost + w3 * string_sim_score
```

重み `w1, w2, w3` は検証データで調整する。デフォルトは `w1=0.6, w2=0.2, w3=0.2`。

---

## 信頼度閾値と人手フラグ

最終スコアに基づいて出力を3段階に分類する。

| スコア範囲 | 判定 | アクション |
|-----------|------|-----------|
| ≥ 0.90 | 高確信 | 自動採用 |
| 0.70 – 0.89 | 中確信 | 候補リスト付きで人手確認 |
| < 0.70 | 低確信 | マッピング不確実フラグ → キュレーターへ |

閾値は運用データに基づいて調整する。

## 日本語対応

日本語論文を扱う場合、追加の翻訳レイヤーが必要。

1. **日英解剖学用語辞書**: 日本解剖学会『解剖学用語』(Terminologia Anatomica 日本語対応) をベースに構築。例: `前頭前皮質 → prefrontal cortex`
2. **漢字表記のゆれ吸収**: `海馬体` / `海馬` / `かいば` の統一
3. **処理フロー**: 日本語入力 → 日英辞書で英語候補に変換 → 以降は英語パイプラインで処理

## HOMBAインデックスの構築

HOMBA CSV（[公式ダウンロード](https://alleninstitute.github.io/CCF-MAP/_downloads/7f807bffb7b40c83221fee6a90148cb7/HOMBA_v1_WORKING.csv)）から以下のインデックスを事前構築する。

```python
@dataclass
class HOMBATerm:
    id: int
    name: str
    acronym: str
    synonyms: list[str]
    parent_id: int | None
    depth: int                    # ルートからの深さ
    normalized_names: list[str]   # 正規化済みの全表記
    embedding: np.ndarray         # SapBERT 埋め込み (事前計算)

# 構築するインデックス
alias_map: dict[str, list[HOMBATerm]]     # Stage 2a 用
bm25_index: BM25Okapi                      # Stage 2c 用
embedding_matrix: np.ndarray               # Stage 3 用 (2341×d)
hierarchy_tree: dict[int, HOMBATerm]       # 階層ブースト用
```

## 評価方針

### データセット

1. **手動アノテーション**: 神経科学論文 50 本から脳領域 mention を抽出し、正解の HOMBA タームを人手で付与（500–1000 件）
2. **既存マッピング**: Allen Brain Atlas API 等の既存データセットで HOMBA への対応関係が既知のものを流用

### メトリクス

| メトリクス | 定義 | 目標 |
|-----------|------|------|
| Accuracy@1 | Top-1 候補が正解 | ≥ 85% |
| Accuracy@5 | Top-5 に正解が含まれる | ≥ 95% |
| Recall@K (Stage 2) | 候補生成段階で正解を拾えている | ≥ 98% |
| Coverage | マッピング可能な mention の割合 | ≥ 90% |

### アブレーション

各コンポーネントの寄与を確認するため、以下の構成を比較する。

- 完全一致のみ
- 完全一致 + あいまいマッチ
- 完全一致 + あいまいマッチ + BM25
- 上記 + SapBERT リランキング
- 上記 + 階層ブースト

## 実装の優先順位

段階的に機能を追加する。

### Phase 1: MVP（1–2週間）

- HOMBA CSV の読み込みとインデックス構築
- 略語辞書の初版（主要 200 件）
- Stage 2a（完全一致 / エイリアス辞書）のみで動くプロトタイプ
- カバレッジの計測

### Phase 2: あいまい検索の追加（1–2週間）

- Stage 1 の前処理パイプライン実装
- Stage 2b（Jaro-Winkler）と 2c（BM25）の追加
- 候補統合ロジック
- Accuracy@1 / @5 の計測

### Phase 3: セマンティックリランキング（2–3週間）

- SapBERT の導入と HOMBA 全タームの事前埋め込み
- Stage 3 の cosine リランキング実装
- 階層ブースト実装
- ハイパーパラメータチューニング

### Phase 4: 運用化（2–3週間）

- 信頼度閾値の最適化
- 日本語対応レイヤー
- API / CLI インターフェース
- ログ収集とエラー分析基盤
