# RCSアルゴリズム仕様資料

2026年6月26日　宮本竜也

## 1. システム概要

ROSETTA Candidate Search（RCS）は、論文等のテキストから抽出された脳領域・解剖学的構造の名称を、HOMBA（Harmonized Ontology of Mammalian Brain Anatomy）の標準タームへ自動変換する検索エンジンである。

HOMBAは Allen Institute が開発した2,341の脳・脊髄構造を含む階層的な種横断オントロジーであり、ヒト・霊長類・げっ歯類の構造間で用語が統一されている。

### 設計原則

- **ゼロ外部依存**: Python標準ライブラリのみで動作し、外部パッケージへの依存を排除
- **高リコール候補生成**: 複数の検索戦略を並列実行し、候補の網羅性を優先
- **辞書駆動の精度改善**: エイリアス辞書・略語辞書によるルールベースの精度向上

## 2. アーキテクチャ

RCSは以下の2段階パイプラインで構成される。

```
Input query (brain region mention)
       │
       ▼
┌──────────────────────────────────┐
│  Stage 1: 前処理・クエリ変換生成   │
│  正規化・エイリアス展開・略語展開   │
│  → 複数のクエリバリアント生成      │
└──────────┬───────────────────────┘
           │
           ▼
┌──────────────────────────────────────────┐
│  Stage 2: 候補生成・スコアリング・ランキング │
│  (a) 完全一致    (b) Fuzzy    (c) BM25    │
│  → union → スコアリング → top-K 出力      │
└──────────────────────────────────────────┘
```

当初は Stage 3 としてSapBERT等の生物医学埋め込みモデルによるセマンティックリランキングを計画したが、脳領域名が短い単語レベルのフレーズであり埋め込み空間の意味距離が十分に機能しない可能性が高いことから、見送りとした。

## 3. Stage 1: 前処理・クエリ変換生成

### 3.1 テキスト正規化（normalize_text）

以下の処理を順に適用する。

1. Unicode NFKC正規化
2. `&` → ` and ` 置換
3. `/` → スペース置換
4. アポストロフィ類（`'`, `` ` ``, `´`）の除去
5. ハイフン・アンダースコア → スペース置換
6. 英数字以外の文字 → スペース置換
7. 連続スペースの圧縮と前後トリム
8. 小文字化

### 3.2 左右情報の除去（strip_laterality）

laterality_words（left, right, bilateral, ipsilateral, contralateral）をクエリから除去する。左右情報は検索対象外とし、メタデータとして保持する。

### 3.3 クエリバリアント生成（query_variants）

入力クエリから以下のバリアントを生成する。

1. 原文
2. 左右情報除去版
3. 括弧内テキスト除去版
4. excluding/except/without以降を除去した版
5. 上記各バリアントにエイリアス辞書を双方向適用した展開版
6. 全バリアントに略語辞書を適用した展開版

### 3.4 修飾語抽出（extract_modifier_terms）

クエリ内の括弧内テキストおよびmodifier_terms辞書に含まれるトークン（anterior, dorsal, lateral等）を修飾語として抽出する。修飾語はStage 2のスコアリングで候補の適合度評価に使用される。

## 4. Stage 2: 候補生成・スコアリング

### 4.1 エイリアスインデックスの事前構築

HOMBAの全エントリについて、以下の情報からエイリアスを展開しインデックスを構築する。

| ソース | 展開方法 |
|--------|---------|
| unified_ontology_name | 括弧分離・カンマ反転・エイリアス辞書適用 |
| unified_ontology_acronym | 同上 |
| DHBA_name | 同上 |
| DHBA_acronym | 同上 |
| hierarchy列 | 同上 |

構築するインデックス:
- **alias_map**: 正規化テキスト → term_index集合（完全一致用ハッシュマップ）
- **token_to_entries**: トークン → entry_index集合（BM25用転置インデックス）
- **BM25統計量**: 文書頻度・平均文書長

### 4.2 完全一致検索（exact）

正規化済みクエリバリアントでalias_mapを直接ルックアップする。ヒットした場合、スコアは1.0（最大確信度）となる。

### 4.3 あいまい文字列マッチング（fuzzy）

以下の4つの類似度指標を重み付き統合する。

| 指標 | 重み | 特徴 |
|------|------|------|
| SequenceMatcher比率 | 0.35 | 最長共通部分列に基づく |
| バイグラムDice係数 | 0.25 | 文字2-gramの共有率 |
| トライグラムDice係数 | 0.20 | 文字3-gramの共有率 |
| トークンJaccard類似度 | 0.20 | 単語レベルの集合類似度 |

加えて、文字列包含ボーナス（一方が他方を含む場合）を適用する。閾値0.45未満の候補は除外する。

検索空間の絞り込みのため、クエリトークンの中で最も稀な2トークンを含むエントリのみを走査する（転置インデックスのintersection）。

### 4.4 BM25トークン検索（bm25）

BM25Okapiアルゴリズムを実装する。パラメータは k1=1.5, b=0.75 である。

スコアの正規化: `normalized_score = raw_score / (raw_score + 4.0)` により [0, 1) の範囲に収める。

### 4.5 最終スコアリング

各候補について以下の統合スコアを計算する。

```
final_score = max(
    hierarchy_parent_score,
    exact_score,
    0.5 * fuzzy + 0.3 * bm25 + 0.2 * token_jaccard,
    0.75 * fuzzy + 0.25 * token_jaccard,
)
```

追加のスコア調整:
- **完全一致ボーナス**: exact_scoreが存在する場合、final_score ≥ 0.96を保証
- **修飾語マッチボーナス**: 修飾語が候補のエイリアスに含まれる場合 +0.12（比例）
- **修飾語不一致ペナルティ**: 修飾語が一つも一致しない場合 ×0.88（上限0.88）
- **特異性ペナルティ**: クエリにない修飾語を候補が持つ場合 ×0.86

### 4.6 共通親ノードプロモーション

2つ以上の兄弟候補が存在する場合、それらの共通の親ノードを候補として昇格させる。昇格スコアは `min(max(子スコア) + 0.08, 0.97)` とする。これにより、「thalamus」のように複数の子ノードが候補に上がるクエリで、適切な粒度の候補が上位に来る。

## 5. 辞書リソース

### 5.1 エイリアス辞書（homba_alias_rules.csv）

同義語や語順の変換規則を定義する。形式は `input_text, homba_text, notes, bidirectional` の4列である。

主なカテゴリ:

| カテゴリ | 例 | 件数 |
|---------|-----|------|
| 一般的な同義語 | amygdala ↔ amygdaloid complex | 約25件 |
| エポニム対応 | heschl gyrus → transverse temporal gyrus | 約15件 |
| ラテン語/英語変換 | fascicle ↔ fasciculus | 約10件 |
| 語順変換 | thalamic nucleus ↔ nucleus of thalamus | 約20件 |
| スペル変換 | occulomotor → oculomotor | 約15件 |
| 方向語の融合/分離 | laterodorsal → lateral dorsal | 約15件 |
| 短縮形/正式名対応 | medulla → medulla oblongata | 約25件 |

### 5.2 略語辞書（homba_abbrev_rules.csv）

クエリ側のみに適用する略語展開規則を定義する。形式は `abbrev, expansion, notes` の3列である。HOMBA側のエイリアス展開には適用しない（短い略語がインデックスを汚染することを防ぐため）。

展開戦略:
- **全クエリ一致**: 任意の長さの略語で適用（例: "lc" → "locus coeruleus"）
- **単語境界置換**: 3文字以上の略語のみ適用（例: "dlpfc" → "dorsolateral prefrontal cortex"）

### 5.3 トークン制御辞書（homba_token_rules.csv）

各トークンの役割を4種に分類する。形式は `term, kind, weight, notes` の4列である。

| 種別 | 役割 | 例 |
|------|------|-----|
| stopword | トークナイズ時に除去 | a, an, of, the, area, region, division |
| laterality | 左右情報として分離 | left, right, bilateral |
| weak | スコアリング時に低重み | anterior, superior, cortex, nucleus |
| modifier | 修飾語として抽出・マッチング対象 | dorsal, lateral, medial, compact |

## 6. 出力フィールド

RCSの出力は以下のフィールドを含む。

| フィールド | 型 | 説明 |
|-----------|-----|------|
| homba_id | string | HOMBAオントロジーID（例: HOMBA:10361） |
| name | string | HOMBA公式名 |
| acronym | string | HOMBA略称 |
| dhba_name | string | DHBA名（発達脳アトラス名） |
| dhba_acronym | string | DHBA略称 |
| parent_id | string | 親ノードのHOMBA ID |
| graph_order | string | グラフ上の順序 |
| depth | int | ルートからの階層深度 |
| score | float | 最終スコア（0.0〜1.0） |
| methods | string | 使用された検索メソッド（例: "exact+fuzzy+bm25"） |
| matched_alias | string | マッチしたエイリアス |
| matched_query | string | マッチに使用されたクエリバリアント |
| best_method_score | float | 最良メソッドの生スコア |
| modifier_terms | string | 抽出された修飾語（セミコロン区切り） |
| modifier_match_score | float | 修飾語の一致度 |
| hierarchy_reason | string | 階層プロモーションの理由（該当時のみ） |

## 7. 性能特性

- **インデックス構築時間**: 約2〜3秒（HOMBA 2,341エントリ）
- **クエリ応答時間**: 約50〜200ms/クエリ（キャッシュ済みインデックス使用時）
- **キャッシュ読み込み時間**: 約0.5秒（pickle形式、Lambda環境）
- **メモリ使用量**: 約50〜80MB（インデックス含む）
