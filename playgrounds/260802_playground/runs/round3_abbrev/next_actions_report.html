3. 推奨アクション（優先順）

  1. P0 エンジン v0.8.3 を本番デプロイ
    WebUI Reports は 0802 だが、検索 API / Lambda が旧 engine のままだと利用者に改善が届かない。 rosetta_candidate_generator.py + homba_abbrev_rules.csv をパッケージし、 S3 辞書同期 → Lambda 更新 → スモーク（VP / DMS / PPN / CA1 / III / dorsolateral PAG）を必須にする。
  2. P1 高信頼 wrong の選択的衝突解消（過学習禁止） — 現在 score≥0.75 の abbrev wrong が 94 件。
    方針: コーパス fullname と整合し、かつ HOMBA に対応ノードがあるものだけルール化。 例: TH（thalamus vs area TH）、dSC（deep SC vs tract）、 pTh（prethalamus）。対応ノードが無い／曖昧なものは broader_parent で止め、無理に exact へ押さない。
  3. P1 複合クエリ前処理（cell-type / marker strip）
    BLA Ppp1r1b、CeA-CRF、NAc-S D1-SPNs、*Glut2 は 解剖 ROI + 分子タグの合成。RCS の仕事は ROI 側。 クエリ正規化で分子・Cre・SPN 接尾辞を剥がし、残った ROI を検索 → 親/本体へ broader_parent を意図的に返す経路を作る（no_match や無関係 exact を減らす）。
  4. P2 multi-token phrase の構造化マッチ （abbrev wrong 最大バケット ≈ multi_token）。
    caudal CP、lateral VTA、spinal interneurons など。 位置修飾 + 核略語は既に一部対応済み。次は （1）残トークンが content のときの部分マッチ強化、 （2）「interneurons / cells / neurons」を弱語化、 （3）fullname 展開との二段検索、を評価する。
  5. P2 fullname 曖昧性（同名異所） — fullname wrong 212、うち高スコア≥0.75 も残存。
    典型: paraventricular nucleus（視床 vs 視床下部）、 arcuate nucleus（延髄 vs 視床下部）。 abbrev 側は ARC で視床下部を明示できた。fullname 側は コーパス種・周辺語・頻度プライア、または「曖昧なら曖昧ラベル」を UI に出す方が、 誤った exact より価値が高い。
  6. P2 broader_parent 上限の扱いをプロダクト方針として固定
    abbrev broader_parent 504 件。頻出親は thalamus / striatum / spinal cord / BNST / NAc。 これは失敗ではなく「HOMBA に文献区画が無い」ことの正しい帰結（DMS 型）。 KPI では aligned+broader を有用率として並記し、親を無理に細分化しない。
  7. P3 評価ハーネス拡張
    （1）回帰セット固定（今回の showcase + high-conf wrong 上位）、 （2）neocortex suitable トラックを別タグで回す、 （3）デプロイ後の本番 API とローカル engine の一致テスト。
  8. P3 UI での説明可能性
    matched_query（文献展開句）と「HOMBA acronym 衝突を抑制した」フラグを WebUI に出し、 VP→ventral pallidum のような判断をユーザーが検証できるようにする。

4. やらないこと（過学習ガード）

  • HOMBA acronym の削除・書換えで衝突を消す（今回の方針と矛盾）。
  • 単発コーパス固有の変則表記だけを exact に押し込むルール乱造。
  • オントロジーに無い区画（多くの striatal compartment）への偽ノード捏造。
  • 判定モデルを毎回変えて「改善したように見せる」こと。審判は Flash×3 固定を継続。
